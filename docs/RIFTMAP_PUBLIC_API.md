# Read-only RiftTowny map API (proposed API 0.4)

## Intended consumer

RiftMap uses RiftTowny for political ownership, **never** Towny Advanced.
The BlueMap plugin still owns terrain rendering, storage and the existing web
server. This interface introduces no HTTP listener, DB query, or map render.

### Obtain the public interface

```java
RiftTownyProvider.get().ifPresent(api -> {
    api.requireApiVersion(new ApiVersion(0, 4));
    RiftTownyMapApi maps = api.mapData();

    // Schedule and rate-limit from the consumer's background executor.
    // Do not do an O(total claims) snapshot on a Folia region/server tick.
    MapRevisions cheap = maps.revisions(); // constant time, no copying
    TerritoryMapSnapshot earth = maps.claims(capturedWorldId);
    CivicMapSnapshot directory = maps.civics();

    // Serialize only relevant, privacy-safe fields from these immutable DTOs.
});
```

The example assumes `capturedWorldId` is a previously obtained UUID captured
through Bukkit on the correct thread, then passed to a background task. Don't
call Bukkit world methods from an arbitrary pool.

## Public value types

- `MapClaim(ChunkKey chunk, UUID townId)`: chunk/world and stable town UUID.
- `TerritoryMapSnapshot(UUID worldId, long revision, List<MapClaim> claims)`:
  complete, immutable world-filtered claim list at one territory-index revision.
- `MapTown(UUID id, String name, Optional<UUID> nationId)`:
  stable town identity, public display name, optional nation identity.
- `MapNation(UUID id, String name, UUID capitalTownId)`:
  stable nation identity, display name, capital **town ID**.
- `CivicMapSnapshot(long townRevision, long nationRevision,
  List<MapTown> towns, List<MapNation> nations)`: immutable public directory.
- `RiftTownyApi.mapData()`: public access point; negotiate API **0.4** first.
- `MapRevisions` from `mapData().revisions()`: cheap counters for polling
  claims and civic metadata without building full snapshots.

## Cache/revision contract

RiftTowny's `TerritoryIndex` has synchronized writer operations and copies
world claims under the same monitor. Hot protection reads remain lock-free
via concurrent-map lookups.

The territory revision is **global within this process**, not per world and
not persistent across restarts. It increases for mutations in any world.
Do not assume increments are gap-free. A consumer can compare the revision
of successive snapshots and discard stale asynchronous rendering results.
On plugin restart, rediscover the API rather than caching an old provider.

Town/nation caches are separately synchronized. Their revisions **are not
an atomic combined transaction revision**: near a nation join, one side may
refresh ahead of the other. Clients should retry when either revision changes
and must not treat temporary missing map metadata as a protection decision.

Check `maps.revisions()` first; its cost is O(1) and does not copy data.
Reload the full snapshot only when its corresponding revision changes.
These counters are not persisted across server restart, so a reconnect must
always obtain at least one fresh snapshot. A global territory revision can
change when an unrelated world changes; this is a safe unnecessary refresh.

Snapshots have O(total cached claims) copying cost and hold a short-lived writer
lock while copying. They **must** be generated by a bounded, rate-limited
async job, not during a protection listener, tick callback, or per HTTP
request. Large maps will later benefit from revision-aware deltas and
bounded pagination, which this PR does not claim to provide.

## Data privacy and missing features

No resident list, UUID of a resident, account balance, personal permissions,
tax settings, plot holder, or internal database connection is exposed here.

This initial API intentionally **does not yet** include:

- claim event subscriptions or per-world delta streams
- nation colors, town spawn coordinates, flags or client visibility controls
- ruin polygons and historic/archived claims
- paginated very-large-world claim enumeration
- an HTTP API, BlueMap polygons or a globe tile exporter

Those remain separate features. In particular, the fact that this API is
available to sibling server plugins does not mean a public map should expose
all snapshots without considering the configured privacy rules.
